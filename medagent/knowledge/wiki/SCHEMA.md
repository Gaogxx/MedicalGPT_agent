# 医药 Wiki 约定（SCHEMA）

这份 Wiki 按 LLM Wiki 的方式维护：**原始资料只读 → 模型编译成带出处的页面 → 自动体检 → 线上缺口回流再编译**。
页面全部由程序生成，不要手改页面；要改内容，改原始资料或编译规则后重新编译。

## 目录结构

| 路径 | 内容 | 生成方式 |
|---|---|---|
| `drugs/<药名>.md` | 每个药一页 | `drug_label_kb.py`（模型抽取 / 核对 / 译写）→ `drug_kb.json` → `wiki.py build` 渲染 |
| `diseases/<病名>.md` | 与 Wiki 药品相关的疾病 | 病名：Wikidata 疾病 + 医学知识图谱“某病的推荐药”病名；药：药品页「适应症」反向链接（经模型复核）+ Wikidata 疾病—治疗药物关系 |
| `index.md` | 目录：药品按 ATC 大类，疾病按 ICD-10 章 | `wiki.py build` |
| `log.md` | 每次编译与体检的记录（只追加） | `wiki.py build` |
| `gaps.md` | 缺口：缺字段的药、线上 `search_drug` 查不到 / 缺字段的药名 | `wiki.py build`（读 `.cache/medagent/wiki_gaps.jsonl`） |
| `_pages.json` | QID → 页面路径、疾病 → 说明书适应症写明本病的药（运行时查找用） | `wiki.py build` |
| `health.md` | 健康报告：体检、页面是否被手改、时效、复核覆盖、隔离区、审核签字 | `wiki_check check`（CI 每周） |
| `audit.md`、`audit_history.jsonl` | 独立抽样复核的报告和历史 | `wiki_check audit`（GPU） |
| `reviews.jsonl` | 药师 / 医生审核签字（带页面内容哈希） | `wiki_check review` |

## 药品页结构

顶部 YAML：`qid`、`name`、`generic_name`、`atc`、`aliases`（含编译时对齐出的新别名）、`kb_tier`（curated / label）、`reviewed: false`、`forms`（有哪些剂型）、`updated`。
正文按顺序：要点 → 适应症（链到疾病页）→ 禁忌 → 用法用量（多剂型时每个剂型一小节）→ 不良反应 → 相互作用（链到其他药品页）→
黑框警告 → 其他剂型的禁忌 / 不良反应 → 同类药物（ATC 前 5 位相同）→ 来源。每一段下面都有 `来源：`。

## 疾病页结构

顶部 YAML：`qid`（Wikidata QID，或 `kg:病名`）、`name`、`aliases`、`icd10`、`reviewed`。正文：说明 → 常见症状（Wikidata）→
**说明书适应症提到本病的药物**（每个药带适应症原句；专用药在前；不是治疗推荐或排序）→ 文献记载的治疗药物（Wikidata）→
**待核对**（知识图谱记的推荐药、但该药说明书适应症没写明本病，只给人看、不给问答模型）→ 来源。

适应症反向链接的规则：病名最长匹配；被更长病名覆盖时只有亚型才同时记上（“2型糖尿病”也记到“糖尿病”）；否定句（不用于 / 禁用 / 尚未确立）不记；
再逐条让模型判断“这段适应症是不是说该药用于这个病”，只是提到病名（“糖尿病等高风险人群”“母体糖尿病时引产”“糖尿病性黄斑水肿”）的剔除。
知识图谱推荐药里，该药说明书禁忌写了这个病的（如维拉帕米禁忌里有“心房颤动合并房室旁路”），即使只是特定情况也保守剔除，数量记进 `log.md`。

## 来源优先级与模型能做什么

1. **精选库**（kb.json，10 个药）：原字段一律保留，训练数据和评测按它。
2. **中文说明书原文**（Huatuo 百科问答 train 拆分）：只允许**原样摘录**或**挑句子编号**（抽取式），不改写。
   每段先过正则（缺数字 / 乱码），再由模型判断是否答非所问、有没有单位或数字损坏；不过就换同药的下一个商品，都不过就留空。
3. **美国 FDA 说明书**（openFDA，优先口服）：只补中文缺的字段。模型译写要点，译文里每个数字必须在英文原文出现，
   再核对有没有原文没有的内容；用法用量注明给药途径和“国内说明书可能不同”。
4. **Wikidata**：药名、别名、ATC、疾病—治疗药物关系。不提供剂量。
5. **要点**：模型只根据本页已有字段概括，不写剂量数字，数字与忠实度核对不过就不写。

模型**不能**：凭记忆补剂量 / 禁忌；在不同剂型之间换算剂量；把类别词（“疫苗”“雄激素”）当具体药。

## 剂型

同一个药的不同剂型（口服 / 注射 / 外用 / 栓剂 / 眼用 / 耳鼻 / 吸入 / 阴道用）分别存用法用量、禁忌、不良反应。
`search_drug` 认出问的剂型时返回该剂型；问到的剂型没有时明确说“知识库没有该剂型的用法用量”，**不给别的剂型的剂量**；
没看出剂型时附上各剂型的用法用量，并提示按所问剂型选用。

## 维护流程

```bash
python -m medagent.knowledge.wiki gaps --names-out gap_names.json          # 线上缺口
python -m medagent.knowledge.drug_label_kb --huatuo huatuo/train.jsonl --openfda-dir openfda \
    --llm http://127.0.0.1:8100/v1 --model compiler --pilot-names gap_names.json   # 重新编译（GPU）
python -m medagent.knowledge.drug_label_kb --summarize --llm http://127.0.0.1:8100/v1 --model compiler
python -m medagent.knowledge.wiki build                                    # 渲染 + 体检，结果追加到 log.md
```

体检项目：断链、孤立页、缺出处的段落、精选库与说明书的剂量数字矛盾、同一别名指向不同药。

## 可靠性机制（定期）

| 频率 | 做什么 | 命令 | 结果去哪 |
|---|---|---|---|
| 每次推送 + 每周（CI，CPU） | 体检、页面与编译结果是否一致（页面不许手改）、距上次编译 / 复核多久、链接复核覆盖率、隔离区、审核签字是否失效；有硬性问题 CI 失败 | `python -m medagent.knowledge.wiki_check check` | `health.md` |
| 每月（GPU 机 cron） | 拉 openFDA 新导出 + 线上缺口药名 → 候选目录全量重编译 → 要点 → 链接复核 → 独立抽样复核 → 体检 → 现行版与候选版端到端评测，过门槛才替换（替换后由人看 diff 提交） | `scripts/wiki_cycle.sh` | `logs/cycle_日期/`、`log.md` |
| 每月（随上一项） | 独立复核：全部已编译字段逐段（约 6,500 段）——Huatuo 摘录先做确定性比对（原样摘录必须是原文子串、抽取的每句都在原文里），再让模型以药师身份对照原文核对；判不通过的由第二次复核确认，两次都不通过才进隔离区（运行时和页面都不再使用）；抽取 / 译写 / 要点只是省略的不隔离，单独列出。`--n 400` 可只做分层抽样 | `wiki_check audit` | `audit.md`、`audit_history.jsonl`、`../wiki_quarantine.json` |
| 随时（人） | 药师 / 医生审核签字：记页面内容哈希，页面显示“已由某某审核”；重新编译改了内容，签字自动失效、回到未审核 | `wiki_check review --page … --reviewer …` | `reviews.jsonl` |

上线门槛（`wiki_check gate`）：候选版和现行版比，药品说明书题覆盖率不降超过 0.01、库外剂量和跨剂型剂量不增加；
某病用药题“有说明书依据”不降超过 0.03、“点出禁忌药”不增加超过 0.01；相互作用题“指出问题”不降超过 0.03、“说可以放心吃”不增加超过 0.01；
原 296 题自动通过率、高风险合规不降超过 0.01。

## 运行时怎么用

- `search_drug`：读 `drug_kb.json`（与页面同源），按剂型返回，每个字段带来源；`MEDAGENT_DRUG_LABELS=0` 关闭。
- `check_interaction`：精选库手写的组合优先；其余在两份说明书的「药物相互作用」段落里互相找对方——点名（药名 / 别名）
  或点类（“非甾体抗炎药”“硝酸酯类”，按 ATC 对上），返回原句和出处；都没提到时说“说明书没提到”，不说“没有相互作用”。
- `search_guideline`：问到用药（或知识库没有该病的指南）时，附上疾病页“说明书适应症写明本病的药”；
  Wikidata 没有、知识图谱有的常见病名（哮喘、抑郁症等）也能查到。
- `search_knowledge`：问题里提到有页面的药 / 病时，按意图挑段落放在证据最前面——问能不能一起吃，先给两份说明书互查的结果和相互作用段；
  问某病用什么药，先给疾病页的药物段；其余仍是全文检索。`MEDAGENT_WIKI=0` 关闭。
- 上面三项新接入的部分 `MEDAGENT_WIKI_TOOLS=0` 一起关掉（回到只看精选库）。
- MCP 资源：`wiki://index`、`wiki://page/{药名或病名}`——给 MCP 客户端（Claude Desktop、DSH 等）和人直接读页面用；
  问答模型走工具，不读资源；模型全部不可用时的降级模式只用精选库，不用 Wiki（未经审核）。
- 缺口：`search_drug` 查不到或缺字段时记药名（不记用户原文）到 `.cache/medagent/wiki_gaps.jsonl`；`MEDAGENT_WIKI_GAPS=0` 关闭。

全部内容未经医生 / 药师审核。
