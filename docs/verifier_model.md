# 开源判别模型：结果校验（替代 Jev）

代码：`medagent/verify/typed.py`（判定定义、校验流程）、`medagent/verify/discriminator.py`（判别模型客户端、输入渲染）；
训练：`training/verifier/01~05`；测试：`tests/test_discriminator.py`。

## 1. 为什么换

原方案接 Jev（TypeSafe AI 的判别模型，早期访问、外部 API），一直没有接入地址，校验实际只用规则；接上以后每个回答都要调一次外部 API。
现在改成自己微调一个开源小模型做判别，部署在本机 vLLM 上：不调外部 API、不按次计费，接口仍然是“程序状态 + 问题 → 预先定义类型的值 + 置信度”。

| 选项 | 结论 |
|---|---|
| 通用评审模型（如 CompassJudger-2-7B） | 输出评语 + 分数，没有校准过的置信度；不了解本项目的失败类型（编造持续时间、工具查不到却给剂量……） |
| 安全分类模型（如 Qwen3Guard） | 只判断内容安全，判断不了漏答、编造、答非所问 |
| **Qwen3.5-2B + LoRA 微调（采用）** | 与本地模型同一系列、同一分词器和对话模板；2B 推理快（每个回答只生成 1 个 token）；按本项目的失败类型和质量等级训练 |

## 2. 判别模型做什么

| 判定 | 类型 | 怎么得到 | 用途 |
|---|---|---|---|
| `answer_quality` | 有序等级：good / acceptable / poor / unsafe | 模型输出一个字母 A / B / C / D，取首 token 在四个字母上的概率 | 监控与抽检；也可作路由标注的免费裁判 |
| `silent_failure` | 是 / 否 + 概率 | P(静默失败) = P(C) + P(D) | **结果校验**：规则没拦住的回答，判断要不要升级重答 |
| `failure_attribution` | 多选一 | **判别模型不做**（没有可靠的训练标签） | 出错归因仍只用规则（受控测试 66/66 判对） |

两个判定来自同一次请求：`max_tokens=1`、`logprobs=true`、`top_logprobs=10`。

输入（`answer_state()` → `build_messages()`，训练与线上用同一套函数）：

```
system：你是医疗问答质检员……只输出一个大写字母
user：  用户问题：…
        助手回答：…（校验前的那版回答）
        工具结果：- found=True {"name": "布洛芬", "dosage": "成人一次0.2g…"}（每个工具结果截 240 字，最多 4 个）
        规则检测：unsupported_detail, …
        安全标记：急症=否，高风险请求=否
        等级：A … B … C … D …（评分标准）
```

## 3. 在流水线里的位置

```
回答 ──► 规则检测器（工具调用泄漏、编造细节、漏答、剂量无依据、急症漏报……）
          │ 命中 block ──► 直接判失败（不问判别模型，确定性优先）
          ▼ 没命中
        判别模型 → p = P(静默失败)
          │ p ≥ block_at             ──► 判失败：网关 / 编排器升级重答（小模型档先升本地模型，本地再升强模型）
          │ review_at ≤ p < block_at ──► 放行，标记 needs_review 进人工复核
          ▼ p < review_at            ──► 放行
        判别模型没部署 / 超时 / 报错 ──► 只用规则，记 disc_error，不影响主流程
```

- 没配置 `MEDAGENT_VERIFIER_URL` 时只用规则（和换之前一样）；
- `block_at` / `review_at` / 温度 T 不手写：部署后由 `evaluation/run_discriminator_eval.py` 在判别器验证集上校准，
  写入 `medagent/verify/artifacts/discriminator.json`，运行时自动读取（没有这个文件时用 0.8 / 0.5 / 1.0）。

## 4. 训练数据

| 来源 | 内容 | 标签 |
|---|---|---|
| 真实回答 | Qwen3.5-2B、Qwen3.5-9B 两个**未微调的基座**在路由数据集 train / val（1,737 题）上走完整编排，记下**校验前**的回答和当时的程序状态 | 百川对照参考答案打的质量等级（一次性约 3,500 次调用）；也可用本机部署的 Qwen3.5-27B 当裁判，不花 API 费 |
| 语义故障注入（只进 train，≤ 真实样本的 35%） | 从判为 good / acceptable 的回答出发：换成别题的回答、截掉后半、剂量放大 4 倍、追加“自行服用抗生素”、追加具体用药 +“不用去医院”、替医生下诊断、急症题删掉 120 / 急诊建议；改完被规则拦下的丢掉 | 按构造：C 或 D |

- 用基座模型而不是等 9B 微调完：判别模型要先训好；基座模型的回答好坏都有，失败样本更多。
- 路由数据集的 test 部分和 dev 80 都不进训练：前者留给路由器报告，后者是判别模型的外部测试。
- val 只用真实样本：温度和阈值要在真实分布上校准。
- 与上一轮的区别：2026-11-05 用合成故障训练的 TF-IDF 分类器在真实失败上 AUROC 只有 0.56（负结果，已默认关闭）。
  这次的训练数据以真实模型回答为主、标签来自裁判，注入的故障也换成了规则抓不到的语义类问题。效果要等训练完在 dev 80 上看。

## 5. 训练与部署（GPU 上，先于 9B 训练）

| 步骤 | 脚本 | 做什么 |
|---|---|---|
| 1 | `training/verifier/01_answers.sh` | 部署两个基座模型，采集回答 + 百川打等级 |
| 2 | `02_data.sh` | 生成 OpenAI 格式（为准）与 MedicalGPT 输入，跑格式一致性测试 |
| 3 | `03_sft.sh` | Qwen3.5-2B bf16 LoRA，3 epoch，按 eval_loss 取最优，合并 |
| 4 | `04_serve.sh` | vLLM :8002，模型名 `medical-verifier`，对话模板与 9B 相同 |
| 5 | `05_eval.sh` | 校准温度和阈值；dev 80 上对比规则（it1 F1 0.69）、旧分类器（AUROC 0.56）、判别模型、规则 → 判别模型级联 |

达标后在 `.env` 里加 `MEDAGENT_VERIFIER_URL=http://127.0.0.1:8002/v1`，再训练 9B（`training/qwen35/01~07`）和路由器（`08`）。
路由标注时校验器里也会包含判别模型，与线上一致。

## 6. 还没做 / 已知限制

- 还没有在 GPU 上训练，没有真实效果数字；
- 判别模型看不到参考答案，用它当路由标注裁判（`--judge verifier`）比百川弱，只在省钱优先时用；
- 训练标签来自百川，判别模型的上限受百川判断质量限制；dev 80 的人工标注是唯一的人工对照。
