# 数据策略 v2：清洗、遮挡增强、配比与防过拟合

## 1. 参考的公开做法（只列来源能证实的部分）

| 项目 | 公开资料里能确认的数据做法 | 本项目借鉴什么 |
|---|---|---|
| 百川 Baichuan-M2（[arXiv 2509.02208](https://arxiv.org/abs/2509.02208)） | 患者模拟器（由脱敏病历与医患对话构建）+ 临床 rubric 生成器做“大型校验系统”；中训练阶段 医疗:通用:数学 = 2:2:1；SFT 约 200 万条中医疗约占 20%；中训练用 KL 约束防遗忘；多阶段 RL | 通用数据回放；“校验器驱动”的数据与奖励（本项目的规则校验器可作为 DPO 在线采样的打分器） |
| 百川 Baichuan-M3（[GitHub](https://github.com/baichuan-inc/Baichuan-M3-235B)） | 问诊过程建模（病史采集→鉴别诊断→检查→诊断四阶段过程奖励）；Fact-Aware RL 把回答拆成原子医学陈述在线核验以抑制幻觉 | “信息不足先追问”的遮挡样本；“每个剂量必须能在证据里找到”的校验规则 |
| 京东健康 Citrus（[arXiv 2502.18274](https://arxiv.org/abs/2502.18274)）/ JoyMed | 继续预训练约 200B token 中医疗约 30%，明确“不能只用医疗语料”；模拟专家推理的长思维链数据；RL 阶段混少量非医疗数据；开源了部分训练数据与 JMED 评测集 | 控制医疗占比、保留通用数据；评测集与训练集严格分离 |
| 蚂蚁 AntAngelMed / 阿福（[GitHub](https://github.com/MedAIBase/AntAngelMed)） | 三阶段：医疗语料继续预训练 → 高质量指令 SFT → GRPO 强化学习（先推理强化再通用强化，兼顾同理心与安全边界）。公开资料未给出数据配比 | 安全边界类样本单独成桶；先保证专业性再做对齐 |
| RAFT（检索增强微调） | 训练时给“真证据 + 干扰文档”，部分样本去掉真证据，让模型学会选证据、没证据时不硬答 | `raft` 增强 |

> 阿福（蚂蚁阿福）本身是 C 端产品，没有找到独立技术报告；上表蚂蚁一行来自安诊儿模型的开源说明。

## 2. v0 数据的问题（`evaluation/results/data_audit_v0.json`，真实统计）

- 三个评测集（eval_sft / eval_dpo / eval_opd）150/150 条**原样出现在训练集**；SFT 训练脚本的验证目录就是训练目录。
- DPO：1500 对里 59% 完全重复、近重复去重后只剩 **65 对**、只有 12 种问法模板；84% 的 chosen 比 rejected 长（长度偏差）。
- 11.5% 的工具调用参数里有**用户没说过的持续时间**（如用户只问“我胃痛怎么办”，参数写 `"duration": "3天"`）——
  这与线上模型回答“您的嗓子疼持续了3天”的幻觉直接对应。
- raw_medical_qa 混入了约 13 条非医疗样本（角色扮演、Python/JS 问题、一条讲 React 组件“副作用”的答案）。
- OPD 数据有 50% 与 SFT 重叠。

## 3. 遮挡 / 造数（`training/scripts/data_pipeline/augment.py`）

每种增强都对准一类真实失败：

| 增强 | 做法 | 对准的失败 |
|---|---|---|
| arg_repair | 删掉无依据的 duration 参数（修复，不新增） | 编造持续时间 |
| slot_mask 槽位遮挡 | 删掉问题里的持续时间，同时删掉工具参数与回答里的对应内容；配一个 rejected=编造“3天”的 DPO 对 | 编造细节 |
| ask_clarify 信息遮挡 | 症状遮成“我不舒服”，目标是结构化追问 + 急症提醒 | 信息不足时乱猜 |
| obs_failure 观察遮挡 | 工具结果换成超时/空/报错，目标是如实说明、不编剂量；rejected=原来基于真实结果的回答 | 工具失败后照样“自信作答” |
| unknown_entity 实体遮挡 | 药名换成库外名字，observation=found:false，目标“查不到”；rejected=编造的说明书 | 查不到时编造 |
| colloquial 口语噪声 | 标准术语换口语/商品名（腹泻→拉肚子、布洛芬→美林）+ 语气词 | 口语说法召回失败 |
| raft 干扰证据 | 1 真证据 + 3 篇 BM25 难负例打乱，20% 去掉真证据（目标“资料不足”） | 被无关证据带偏 |

所有增强样本带 `meta.aug` 与 `meta.orig_query`，切分时跟原句同组；回答模板做了多版本改写，避免新一轮“背模板”。

## 4. 配比（`training/configs/data_mix_v2.yaml`）

| 来源 | 目标占比 | v2 实际 |
|---|---|---|
| 真实医疗问答 | 33% | 1716 |
| 工具调用轨迹（已修复参数） | 30% | 1560 |
| 槽位遮挡 / 观察遮挡 / 实体遮挡 / 口语 / RAFT / 追问 | 合计 28% | 1251（追问模板去重后只剩 1 条，需要更多样的种子） |
| 安全类（急症 / 拒开方） | 4% | 28（v0 DPO 安全样本去重后很少，**需补**） |
| 通用回放 | 5% | 11（**需提供通用指令数据**，如 BelleGroup 抽样，填 `general_replay_path`） |

原则：真实数据为主，增强合计 ≤ 30%（实际 27.4%）；每条原始样本最多 2 个增强变体；同一问法模板最多 25 条。

## 5. 防过拟合清单

数据侧：评测集与训练集互斥（含新评测集）；按问法模板分组切分（v2 验证集近重复泄漏 6.6% → 0.27%）；模板上限；近重复去重；通用数据回放。
训练侧（`sft_train_v2.sh` / `dpo_train_v2.sh`）：独立验证集 + 按 eval_loss 取最优检查点；SFT 3→2 epoch、NEFTune（`--neft_alpha 5`）、
lora_dropout 0.05→0.1、weight decay；DPO 约 1 epoch、开评估、beta 0.1→0.2、RPO（chosen 上叠加 NLL，防止 chosen 似然一起下降）。
MedicalGPT 原 DPO 脚本不透传 beta 等参数，`patch_medicalgpt_dpo.py` 负责补上。
监控：DPO 的 eval rewards/accuracies 若 > 0.95 且 eval loss 回升即判定过拟合。

## 6. v3：把条数补够（2026-11-09）

v2 去重后 SFT 4,566 条、DPO 365 对，太少。v3 的补法（`training/scripts/data_pipeline/supplement.py` → `augment.py` → `mix_v3.py`）：

| 来源 | 做法 | 进入 v3 的条数 |
|---|---|---|
| 真实医疗问答 | Huatuo 百科问答 + Huatuo26M-Lite（数据集自带质量分 ≥4），长度/广告/去重/医疗性过滤，与所有评测集去污染 | 11,960 → 全局去重后约 9.5k |
| 原工具调用轨迹 | 修复无依据参数 | 2,579 |
| 扩展工具轨迹 | observation 来自**真实调用工具**（精选 KB + Wikidata 2.4k 疾病 / 2.5k 药物），问法 15 种、回答多版本；Wikidata 药没有剂量时回答明确说“请查说明书” | 4,420 |
| 遮挡 / 反事实 | 槽位遮挡、观察遮挡、实体遮挡、口语化（在新轨迹上生成） | 1,437 |
| RAFT | 真证据 + 3 篇难负例，20% 无真证据 | 1,040 |
| 安全 / 追问 | 组合生成，去重后大量坍缩（见下） | 363 / 44 |
| 通用回放 | alpaca-zh（CC-BY-4.0） | 1,300 |
| DPO 真实偏好对 | shibing624/medical reward（3,800 对 → 过滤 2,752 → 长度平衡后约 1.4k） | 见 manifest |
| DPO 反事实 / 安全 | augment 反事实 1,200 + 安全 356 | |

结果（`training/data/data_v3_manifest.json`，审计 `evaluation/results/data_audit_v3.json`）：
**SFT 20,663 条（train 19,601 / val 1,062），真实数据约 68%；DPO 2,971 对（train 2,765 / val 206）**；
验证集与训练集同问题 0、近重复 0.19%；无依据参数 0.06%；问法模板唯一率 91%；DPO chosen 更长的比例 59%。

v3 暴露并处理的问题：
- **Wikidata“疾病—症状”关系会教坏模型**：“过度充血”→“鼠疫、克里米亚-刚果出血热”。这类关系没有发病率排序，已从训练数据和运行时工具中移除，Wikidata 只保留药品 / 疾病的实体信息；
- **跨来源重复**：同一问题同时出现在 Huatuo 百科与 Lite，只做来源内去重会让它落到 train/val 两侧（泄漏 1.49%）→ 切分前全局去重；
- **真实偏好对的长度偏差**：72% 的 chosen 更长 → 平衡到 59%（代价：真实对少了约一半）。也可以设 `max_chosen_longer_share: 1.0` 保留全部，再在训练时用长度归一化损失（如 SimPO / IPO）；
- **组合模板的坍缩**：安全样本 1,018 → 363、追问 600 → 44——回复只有几种固定说法，去重机制正确地把它们当成了重复。真正扩充需要由强模型逐条生成、医生审核（需 API 与人力）。

## 7. 还没做、需要资源的

1. **在线偏好对**：用当前模型对每个问题采样 N 个回答，用本项目的校验器 + 强模型 rubric 打分构造 chosen/rejected（Baichuan-M2 的“校验器驱动”思路）——需 GPU 跑本地模型 + 强模型 API。
2. 安全类与追问类种子扩充到数百条（最好由医生审核）。
3. 通用回放数据。
4. 用 v2 数据重训 SFT → DPO，再在 dev + 独立集上跑回答层评测，才能知道模型侧真实提升——本轮没有 GPU，**模型本身没有重训**。
